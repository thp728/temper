The import surface: a form, a journey, and the decision record

The browser journeys and the web shell get the import step (issue #45): a
card on the upload page lets a user start from a public repository, with an
optional configuration and split, and the imported rows land on the same
validation report an upload produces. The journey imports against the same
fake resolver the pytest suite uses (TEMPER_FAKE_PROVIDER swaps the
remote-dataset seam for a canned fake, exactly as it swaps the provider), so
the journeys reach no network. The e2e ports move to this issue's range
(4530/4531) so this worktree's journeys cannot reuse or collide with a
sibling's servers.

The decision record (ADR-0044) records the import-by-reference shape: one
validation path, the seam living in the control plane because it is network
I/O, refusals up front with their reasons, and the size ceiling read from the
same configuration an upload reads.
